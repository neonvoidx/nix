[![Build and Cache](https://github.com/neonvoidx/nix/actions/workflows/build-and-cache.yml/badge.svg?branch=master)](https://github.com/neonvoidx/nix/actions/workflows/build-and-cache.yml)

## Key Features

- **den Framework** — auto-generates `nixosConfigurations`, wires Home-Manager, provides `host`/`user` context
- **import-tree** — all `.nix` files under `modules/` are auto-discovered; no manual wiring needed
- **Aspect Pattern** — every feature is a self-contained file with optional `nixos` and `homeManager` sections
- **Host Context** — freeform attributes on hosts (`monitors`, `audio`, `network`, `isGaming`, `isLaptop`, `xRes`, `yRes`, `gpuPciDev`, `gpuVendorDeviceId`, `nasIp`, `printerUri`, `greeting`, `timezone`, etc.) accessible in any aspect
- **User Context** — user attributes (`userName`, `homeDirectory`, `gitName`, `gitEmail`, `emailName`, `emailAddress`) accessible in any aspect
- **Hyprland** — Wayland compositor with Lua config, multi-monitor layouts, HDR support, game workspace management
- **Umbriel** — scrolling Wayland compositor with dynamic, output-local workspaces: horizontal strips on landscape monitors and vertical strips on rotated portrait monitors. On the desktop, applications default to the main output; Discord and Spotify open in separate lanes on portrait workspace 1 at 75%/25% height, while Discord popouts use the secondary output. A session listener maintains the Discord/Spotify arrangement. Games open fullscreen. Mod+1–0 selects local workspace positions; Mod+S/G/T/D focuses existing Steam/game/Thunderbird/Discord windows. The monitor toggle directly switches DP-2's display power without migrating workspaces.
- **Stylix** — System-wide theming (base16, GTK, Qt, fonts) in one aspect file
- **Discord** — Native client via nixcord (Discord + Equicord + OpenASAR) as a systemd user service, theme + selection color injected through `stylix.targets.nixcord`
- **SOPS** — Age-encrypted secrets, decrypted to `/run/secrets/` at boot via systemd service
- **Noctalia Shell** — Quickshell bar, launcher, lock screen
- **nvim** — Neovim config from `neonvoidx/nvim` via flake input
- **nh flake apps** — `nix run .#void` / `nix run .#voidframe` for building with nh
- **Tmux + sesh** — one picker (`s`, prefix+o via `display-popup`, shell start) listing all sources; resurrection saves run from a systemd timer, not continuum
- **Conditional Includes** — aspects gated by `host.isGaming or false` via `lib.optionals`

> **AI Agents:** See [`AGENTS.md`](./AGENTS.md) for detailed context when working with this flake.

## Umbriel Keybindings

`Mod` is Super. Arrow keys mirror H/J/K/L for focus and movement.

| Binding | Action |
| --- | --- |
| Mod+H/J/K/L | Focus left/down/up/right, crossing outputs at the layout edge |
| Mod+S / Mod+G / Mod+T / Mod+D | Focus an open Steam / game / Thunderbird / Discord window |
| Mod+Shift+H/L | Move left/right, crossing outputs at the layout edge |
| Mod+Shift+J/K | Move down/up, crossing to the next/previous workspace at the layout edge |
| Mod+= / Mod+- | Increase/decrease lane extent by 5% |
| Mod+R | Cycle lane extent: 33%, 50%, 75%, 100% |
| Mod+C | Center a floating window |
| Mod+Shift+Space | Toggle floating |
| Mod+WheelUp/Down | Previous/next workspace |

The old S/T workspace shortcuts and their Shift variants are removed. App-focus shortcuts do nothing if no matching window is open. There is no resize submap. Toggles, app launches/focus, screenshots, close/quit/lock, direct workspace selection and sending, centering, Alt+Tab, size cycling, and track changes run once per press (`repeat = false`). Directional focus/movement, incremental resizing, volume, and brightness retain repeat; wheel workspace navigation is unchanged. Keyboard typing repeats at 25 Hz after a 600 ms delay; `input.keyboard.repeat_rate = 0` disables held-key typing independently of per-keybind repeat flags. New scrolling windows default to 90% of the viewport; fullscreen games and the portrait Discord/Spotify 75/25 split keep their explicit rules. On a vertical strip, primary extent adjusts lane height; on a horizontal strip, it adjusts column width. Directional actions follow screen directions: on the portrait output, left/right reorder windows within a lane. The Discord/Spotify listener restores their separate lanes' ordering and sizes when either app reopens. Restart the Umbriel session after installing this change to start the listener.

## Firefox Preferences

Firefox uses the `betterfox-nix` Home Manager module, locked through the
`betterfox` flake input, with preset `154.0` selected in
`modules/desktop/firefox.nix`. Personal changes to Betterfox's AI, geolocation,
search, and prefetch preferences use its category settings. Other preferences
and toolbar customization remain in `extraConfig`, applied afterward. Whole
categories remain enabled to preserve their other protections. Updating the
flake input updates the module; changing the selected preset is a separate,
deliberate update.

## Usage

```bash
# Validate configuration
nix flake check
nix-agent_check --level lint
nix-agent_check --level dry-build

# Build without activating
nix-agent_build

# Diff against running system
nix-agent_diff

# Deploy
nix-agent_switch

# Or use nh flake apps
nix run .#void
nix run .#voidframe

# Update flake inputs
nix flake update

# Add or change a flake input: edit modules/flake-inputs.nix, then regenerate flake.nix
nix run .#write-flake

# Format all .nix files
nix-agent_format
```

## Den Framework Pattern

Each feature is a self-contained **aspect** file. NixOS and Home-Manager config for the same program live together:

```nix
# modules/audio/pipewire.nix
{ den, ... }:
{
  den.aspects.pipewire = {
    nixos = { pkgs, ... }: {
      services.pipewire.enable = true;
    };

    homeManager = { ... }: {
      # user-level config if needed
    };
  };
}
```

To access **host or user context**, use the outer aspect lambda:

```nix
{ den, lib, ... }:
{
  den.aspects.example =
    { host, user, ... }:
    {
      nixos = { pkgs, lib, ... }: {
        # host.hostName, host.monitors, host.xRes, host.yRes
        # host.isMultiMonitor or false, host.isLaptop or false, host.isGaming or false
        # host.gpuPciDev, host.gpuVendorDeviceId, host.audio, host.network
        # host.greeting, host.timezone, host.nasIp, host.printerUri
        # Note: networking.hostName is set automatically by den._.hostname
      };

      homeManager = { osConfig, ... }: {
        # user.userName, user.homeDirectory, user.gitName, user.gitEmail
        # user.emailName, user.emailAddress
        # osConfig accesses the NixOS config (e.g. osConfig.fileSystems ? "/games")
        home.file."example".text = "hello ${user.userName}";
      };
    };
}
```

> **Note:** `host` and `user` are only available in the **outer** aspect lambda, not inside `nixos`/`homeManager` module args. Capture them via Nix's lexical scoping (they are automatically in scope for inner lambdas).

> **Note:** Host attributes are freeform — use `host.isLaptop or false` when an attribute may not exist on all hosts.

For **conditional includes** with `lib.optionals`:

```nix
{ den, lib, ... }:
{
  den.aspects.example =
    { host, ... }:
    {
      includes = [
        den.aspects.steam
        den.aspects.mangohud
      ]
      ++ lib.optionals (host.isGaming or false) [
        den.aspects.deadlock
        den.aspects.wow
      ];
    };
}
```

Both hosts explicitly include `den.aspects.base-system`, defined in `modules/system/base-system.nix`, for their 17 shared system aspects. The `void` host adds WireGuard, network drives, and gaming; hardware and host-specific settings stay in the individual host modules. The `void` host reads its static network settings from `host.network` in `modules/hosts.nix`, keeping DNS, IP, prefix length, gateway, interface, and MAC address in one place.

## Adding a New Aspect

1. Create `modules/<category>/my-feature.nix` — import-tree picks it up automatically
2. Add `den.aspects.my-feature` to the user's includes in `modules/users/neonvoid/neonvoid.nix` (for user-facing features) or to the host's includes in `modules/hosts/<hostname>/default.nix` (for system-only features)
3. Rebuild

```nix
# modules/category/my-feature.nix
{ den, ... }:
{
  den.aspects.my-feature = {
    nixos = { pkgs, ... }: {
      services.myservice.enable = true;
    };

    homeManager = { pkgs, ... }: {
      programs.myservice.enable = true;
    };
  };
}
```

## Adding a New Host

1. Add the host to `modules/hosts.nix`:

```nix
den.hosts.x86_64-linux = {
  mynewhost = {
    users.neonvoid = neonvoid;  # reuse the user attrset defined in the let block

    monitors = {
      main = {
        name = "DP-1";
        mode = "1920x1080@60";
        scale = 1.0;
        position = "0x0";
        primary = true;
      };
    };

    xRes = "1920";
    yRes = "1080";

    # Optional — add any freeform attributes your aspects need:
    # gpuPciDev = "0000:01:00.0";
    # audio = { defaultMic = "..."; defaultSpeaker = "..."; };
    # network = { wireless = true; };
    # isLaptop = true;
    # isGaming = false;
    # greeting = "My Host";
    # timezone = "America/New_York";
  };
};
```

2. Create `modules/hosts/mynewhost/default.nix`:

```nix
{ den, inputs, ... }:
{
  den.aspects.mynewhost = {
    includes = [
      # Core system
      den.aspects.boot
      den.aspects.locale
      den.aspects.networking
      den.aspects.systemd
      den.aspects.overlays
      den.aspects.nixsettings

      # Hardware
      den.aspects.bluetooth
      den.aspects.kernel
      den.aspects.udev

      # Security
      den.aspects.sops
      den.aspects.pcscd
      den.aspects.noctalia-greeter
      den.aspects.polkit

      # System packages
      den.aspects.systempackages
    ];

    nixos = { lib, ... }: {
      imports = [ (inputs.self + "/hosts/mynewhost/hardware-configuration.nix") ];
      # hostname is set automatically from den._.hostname (host name = "mynewhost")
      # boot, hardware, networking specifics...
    };
  };
}
```

3. Add `hosts/mynewhost/hardware-configuration.nix` (from `nixos-generate-config`).

That's it — den auto-generates the `nixosConfiguration` output from `hosts.nix`.

## Adding a New User

1. Create `modules/users/<username>/<username>.nix`:

```nix
{ den, lib, ... }:
{
  den.aspects.<username> =
    { ... }:
    {
      includes = [
        den.aspects.zsh
        den.aspects.git
        # ... all aspects this user should have, look at neonvoid for full list
      ];

      nixos = { ... }: {
        # den._.define-user, den._.primary-user, and den._.user-shell handle
        # isNormalUser, shell, and wheel automatically — only add extras here
        users.users.<username> = {
          extraGroups = [ "audio" "video" "networkmanager" ];
        };
      };
    };
}
```

2. Add the user to the host entry in `modules/hosts.nix`:

```nix
mynewhost = {
  users.myuser = {
    gitName = "My Name";
    gitEmail = "me@example.com";
    emailName = "My Name";
    emailAddress = "me@example.com";
  };
};
```

## Project MCP Servers (Codex)

`.codex/config.toml` registers [mcp-nixos](https://github.com/utensils/mcp-nixos)
for package/option discovery and [nix-agent](https://github.com/JEFF7712/nix-agent)
for configuration inspection and validation. Both launch through `uvx`, with
pinned versions. Trust this project in Codex and reopen the session after changing
the configuration. This is separate from the Home Manager MCP declarations in
`modules/shell/mcp.nix`.

Prerequisites: `uvx` and Nix on PATH; nix-agent lint additionally needs `statix`
and `deadnix`. The Python launch does not bundle the Nix wrapper's helper tools.
Linux closure builds require a compatible builder; live-system diffs require a
running NixOS system. The checked-in `NIX_AGENT_FLAKE` points to this Mac's checkout;
adjust it for other checkout locations and pass an explicit `flake_uri` ending in
`#void` or `#voidframe` when selecting a host.

Activation and rollback tools are excluded. Use `check` only with `lint` or
`dry-build`, never `dry-activate`; Codex's tool allowlist cannot restrict individual
argument values. No system activation or passwordless sudo setup is part of this
configuration.

## Screenshots

Hyprland and Umbriel use the same Noctalia screenshot shortcuts: Print selects a region, Shift+Print opens screenshot annotation, and Ctrl+Print captures all outputs. Hyprland's former Mod+Shift+C color-picker binding has been removed.

## Tmux Desktop Environment

Hyprland and Umbriel refresh tmux's desktop environment on startup. Existing Zsh panes pick up current socket variables at their next prompt, including clearing the previous compositor's IPC variable. This setup targets local desktop attachments. After deploying the change, restart existing pane shells or load the updated Zsh configuration once; already-running applications must be restarted to inherit changed variables.

Tmux snapshots use the existing 10-minute user timer. Continuum handles automatic restoration only; its autosave is disabled because the custom status line replaces its save trigger.

Tmux's prefix+r resize mode applies only to the current client and displays `RESIZE` in its status line. Use hjkl or arrows to resize; q, Escape, or Enter exits. Other keys are ignored while resizing.

The prefix+o session picker and prefix+W window picker open in the current pane's directory. The session picker shares its options across shell, pane, and popup entry points.
